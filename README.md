# 초기 플랫폼 출시 범위와 IGDB 평가 참여 패턴 분석

게임이 최초 출시된 후 30일 이내의 플랫폼 범위가 이후 누적 평가 참여 패턴과 어떤 관계가 있는지 분석한 프로젝트입니다.

2017~2025년 IGDB 게임 데이터를 활용해 초기 단일·멀티플랫폼 게임의 전체 차이, 장르·연도별 반복성, 플랫폼 수와 평가 참여의 관계 및 예외 조건을 확인했습니다.

[🚀 Streamlit 대시보드 바로가기](https://igdb-platform-scope-analysis.streamlit.app/)

---

## 1. 프로젝트 배경

게임 이용자는 모바일·PC·콘솔 등 여러 플랫폼에서 게임을 이용하며, 플랫폼마다 이용자 규모와 시장 구조가 다릅니다.

- 2025년 게임이용자 조사: 모바일 89.1%, PC 58.1%, 콘솔 28.6%
- 2024 대한민국 게임백서: 국내 게임시장 매출 비중 모바일 59.3%, PC 25.6%, 콘솔 4.9%

멀티플랫폼 출시는 더 많은 이용자와 접점을 만들 수 있지만, 플랫폼 추가에 따라 전용 개발 장비, 라이선스, 코드 수정 등의 비용이 발생할 수 있습니다.

따라서 이 프로젝트에서는 멀티플랫폼 출시가 항상 유리하다고 가정하지 않고, 초기 플랫폼 출시 범위와 공개 평가 참여 사이에서 관찰되는 패턴을 분석했습니다.

> 이 프로젝트에서 `평가 수`는 판매량이나 전체 이용자 수가 아닌, IGDB 이용자의 공개 평가 참여를 나타내는 대리지표입니다.

---

## 2. 핵심 분석 질문

모든 질문에서 플랫폼 수는 게임의 전체 플랫폼 수가 아니라 **최초 출시 후 30일 이내의 고유 플랫폼 수**를 의미합니다.

1. 초기 단일·멀티플랫폼 게임의 평가 수와 이용자 평점은 다른가?
2. 평가 참여 차이는 장르와 출시 연도별로도 반복되는가?
3. 초기 플랫폼 수와 평가 참여의 관계는 얼마나 강하며, 반대 사례는 무엇인가?

## 4. 분석 기준

### 초기 플랫폼 범위

게임의 전체 플랫폼 수를 사용하면 흥행 이후 다른 플랫폼으로 이식된 기록까지 초기 출시 전략에 포함될 수 있습니다.

이를 줄이기 위해 다음과 같이 초기 플랫폼 범위를 정의했습니다.

```text
초기 플랫폼 범위 = 최초 출시일부터 30일 이내 출시된 고유 플랫폼 수
```

| 초기 플랫폼 수 | 분류 |
|---:|---|
| 1개 | `single` |
| 2개 이상 | `multi` |

30일은 후속 이식 기록이 초기 출시 범위에 포함되는 문제를 줄이기 위한 운영 기준입니다. 유일하게 정답인 기간을 의미하지는 않습니다.

### 평가 참여 지표

- 실제 결과 설명: `rating_count` 중앙값
- 분포 시각화: `log1p(rating_count)`
- 플랫폼 수와의 관계: Spearman 순위상관계수
- 장르×연도 비교: 단일과 멀티 그룹이 각각 10개 이상인 조합만 포함

## 5. 전처리 과정

### 1. 분석 대상 선정

- 2017~2025년 출시 게임
- 본편 게임
- 상위 게임이나 다른 버전이 아닌 게임
- 제외 대상 출시 상태 제거
- 이용자 평점과 평가 수가 존재하는 게임
- 평가 수가 1건 이상인 게임

### 2. 출시 기록 정규화

IGDB의 중첩된 출시 기록을 다음 단위로 펼쳤습니다.

```text
게임 ID × 플랫폼 ID × 플랫폼 출시일
```

이후 다음 기준을 적용했습니다.

- 일 단위까지 확인 가능한 정확한 출시일만 사용
- 플랫폼 ID와 출시일이 없는 기록 제외
- 동일 게임·플랫폼의 중복 기록 제거
- 최초 출시일 이전의 플랫폼 기록 제외
- 최초 출시 후 30일 이내 플랫폼만 집계

### 3. 장르 정리

- 장르명을 문자열로 변환
- 중복 장르 제거
- 장르명 정렬 및 표준화
- 장르가 없는 게임 제외

### 4. 파생변수 생성

- `release_year`
- `initial_platform_count_30d`
- `initial_platform_group`
- `rating_count_log`

최종적으로 게임 ID가 중복되지 않는 **6,244개 게임 × 9개 변수**의 분석 테이블을 생성했습니다.

## 6. 핵심 분석 결과

### 질문 1. 초기 단일·멀티플랫폼의 전체 차이

| 구분 | 게임 수 | 평가 수 중앙값 | 이용자 평점 중앙값 |
|---|---:|---:|---:|
| 초기 단일플랫폼 | 2,601개 | 5건 | 70점 |
| 초기 멀티플랫폼 | 3,643개 | 9건 | 70점 |

초기 멀티플랫폼 게임의 평가 수 중앙값은 초기 단일플랫폼보다 약 **1.8배 높았습니다.**

반면 이용자 평점 중앙값은 두 그룹 모두 70점으로 같았습니다. 초기 멀티플랫폼 게임은 더 많은 공개 평가 참여와 연관됐지만, 더 높은 이용자 평점과 연결되지는 않았습니다.

### 질문 2. 장르·연도별 반복성

장르와 출시 연도가 같은 게임끼리 비교하고, 단일·멀티 그룹이 각각 10개 이상인 조합만 분석했습니다.

| 결과 | 조합 수 |
|---|---:|
| 비교 가능한 장르×연도 조합 | 120개 |
| 멀티플랫폼 평가 참여 중앙값 우세 | 103개 |
| 단일플랫폼 평가 참여 중앙값 우세 | 12개 |
| 중앙값 차이 없음 | 5개 |

전체 조합의 **85.8%**에서 초기 멀티플랫폼 게임의 평가 참여 중앙값이 더 높았습니다.

따라서 전체 비교에서 확인된 방향은 특정 장르나 연도에만 한정되지 않고 여러 조건에서 대체로 반복됐습니다.

### 질문 3. 플랫폼 수와 평가 참여의 관계

초기 멀티플랫폼 게임 3,643개를 플랫폼 수에 따라 구분했습니다.

| 최초 출시 후 30일 이내 플랫폼 수 | 실제 평가 수 중앙값 |
|---|---:|
| 2개 | 7건 |
| 3개 | 8건 |
| 4개 | 11건 |
| 5개 이상 | 15건 |

플랫폼 수 구간이 증가할수록 평가 수 중앙값도 증가했습니다.

그러나 개별 게임의 초기 플랫폼 수와 평가 참여 사이의 Spearman 순위상관계수는 다음과 같습니다.

```text
Spearman ρ = 0.197
```

양의 방향은 관찰됐지만 관계의 강도는 약했습니다. 따라서 플랫폼 수만으로 개별 게임의 평가 참여를 충분히 설명하기는 어렵습니다.

### 대표 예외

`Tactical` 장르의 2020년 게임에서는 전체 경향과 반대되는 결과가 나타났습니다.

| 구분 | 게임 수 | 실제 평가 수 중앙값 |
|---|---:|---:|
| 초기 단일플랫폼 | 12개 | 15.5건 |
| 초기 멀티플랫폼 | 17개 | 5건 |

이 분석만으로 예외가 발생한 원인까지 판단할 수는 없습니다.

## 8. 실행 방법

### 요구 사항

- Python 3.12 이상
- [uv](https://docs.astral.sh/uv/)

### 저장소 복제

```bash
git clone https://github.com/MainHHH/igdb-platform-scope-analysis.git
cd igdb-platform-scope-analysis
```

### 의존성 설치

```bash
uv sync
```

### 대시보드 실행

저장소에 포함된 전처리 완료 데이터를 사용하므로 IGDB 인증 정보 없이 대시보드를 실행할 수 있습니다.

```bash
uv run streamlit run app.py
```

실행 후 터미널에 표시되는 로컬 주소로 접속합니다.

```text
http://localhost:8501
```

## 9. 데이터 수집부터 재현하기

원본 데이터를 다시 수집하려면 IGDB API 사용을 위한 Twitch 애플리케이션 인증 정보가 필요합니다.

- [IGDB API 인증 안내](https://api-docs.igdb.com/#account-creation)
- [Twitch Developer Console](https://dev.twitch.tv/console/apps)

### 환경변수 설정

프로젝트 루트에 `.env` 파일을 생성합니다.

```env
IGDB_CLIENT_ID=YOUR_CLIENT_ID
IGDB_CLIENT_SECRET=YOUR_CLIENT_SECRET
```

`.env` 파일은 Git에 포함되지 않으며, 실제 인증 정보를 저장소에 커밋하면 안 됩니다.

### 원본 데이터 폴더 생성

```bash
mkdir -p data_collection/raw_data
```

### 데이터 수집

```bash
uv run python data_collection/collect_data.py
```

다음 파일이 생성됩니다.

```text
data_collection/raw_data/games.json
data_collection/raw_data/games.csv
```

### 데이터 전처리

```bash
uv run python preprocessing/process.py
```

전처리 결과는 다음 위치에 저장됩니다.

```text
preprocessing/processed_data/games_processed.csv
```

### 대시보드 실행

```bash
uv run streamlit run app.py
```

> IGDB 데이터는 수집 시점에 따라 변경될 수 있으므로 데이터를 다시 수집하면 게임 수와 분석 결과가 달라질 수 있습니다.

## 12. 분석의 한계

1. **선택 편향**  
   이용자 평점과 평가 수가 존재하는 게임만 분석에 포함했습니다.

2. **평가 수의 의미**  
   평가 수는 판매량이나 전체 이용자 수가 아니라 IGDB 이용자의 공개 평가 참여를 나타내는 대리지표입니다.

3. **누적값 사용**  
   초기 플랫폼 범위는 최초 출시 후 30일을 기준으로 하지만, 평가 수는 데이터 수집 시점까지 누적된 값입니다.

4. **외부 요인 미통제**  
   게임 품질, 브랜드 인지도, 마케팅 비용, 가격, 개발사 규모 등의 요인을 통제하지 못했습니다.

5. **운영 기준의 한계**  
   30일과 그룹별 최소 표본 수 10개는 비교의 일관성과 안정성을 위한 운영 기준입니다.

6. **다중 장르**  
   하나의 게임이 여러 장르에 포함될 수 있으므로 장르×연도 조합은 서로 완전히 독립적이지 않습니다.

따라서 분석 결과는 인과 효과가 아니라 **관찰된 차이와 연관성**으로 해석해야 합니다.

## 13. 향후 개선 방향

- 최초 출시 후 7일·30일·60일·90일 기준 민감도 분석
- 출시 후 경과 기간을 반영한 평가 참여 속도 분석
- 판매량, 실제 이용자 수, 가격, 마케팅비 등 추가 변수 결합
